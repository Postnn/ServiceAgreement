# ServiceAgreement — параметры договоров оказания услуг

Минималистичное графическое Windows 10/11 x64 приложение на Go (Win32/Walk).
Предназначено для редактирования `dbo.[ДокументыДоговораОказанияУслуг]` в Microsoft SQL Server.
Не требует установленного Go, .NET, ODBC-драйвера или запуска собственного сервера.

## Быстрый запуск

1. Скачайте `ServiceAgreement-windows-amd64.zip` из последнего GitHub Release.
2. Распакуйте в папку с правом записи (для изменения настроек понадобится запись в `config.json`).
3. Запустите `ServiceAgreement.exe` и откройте **«Настройки SQL и колонок…»**. Введите строку подключения к SQL Server.
4. В окне настроек можно проверить соединение, исправить SQL-запросы и настроить колонки. Нажмите «Сохранить».
5. Выберите договор в списке, дважды щёлкните или нажмите «Изменить».

Рядом с EXE находится `config.json` (образец — `config.example.json`). Если конфигурации нет или БД недоступна, основное окно всё равно открывается: можно зайти в настройки, не редактируя JSON вручную.
Изменения в конфигурации применяются сразу; при сохранении существующий `config.json` копируется в `config.json.bak`. Не публикуйте реальные конфигурации с секретами в GitHub.

## Главное окно

- **Поиск по договору**: введите строку и нажмите **Enter** или кнопку **«Найти»**. Пустая строка показывает обычный список. **«Обновить»** повторяет текущий запрос.
- Отображение строк определяется двумя *разными* SQL-запросами: `list_sql` (при пустом поиске) и `search_sql` (при непустом `@search`).
- **Структура колонок определяется SQL.** Программа сравнивает результаты `list_sql` и `search_sql` (даже если они вернули ноль записей). Новые SQL-алиасы автоматически попадают в `list_columns` **видимыми по умолчанию**. Удаление настроек полей, исчезнувших из SQL, требует подтверждения. Настроенные названия, ширина, порядок, `sortField` и видимость существующих колонок сохраняются.
- Раздел «Колонки списка…» служит только для настройки отображения. Поле `field` не редактируется, а ручного добавления/удаления колонок нет: измените `SELECT`, затем нажмите «Обновить поля из SQL».
- Для выбора/редактирования записи SQL-запрос должен вернуть `ContractID` (целое положительное число). Другие поля могут быть произвольными алиасами SQL. Вычисляемые значения должны возвращаться непосредственно SQL-запросами.

## Форма редактирования

Вместо четырёх полей поиска и выбора здесь **два поля**:

- **Договор** — редактируемый выпадающий список (изменение договора существующей записи запрещено).
- **Тип документа основания автооплаты** — редактируемый выпадающий список.

Введите код или часть названия прямо в поле и нажмите **Enter**. Если запрос найдёт **одно** совпадение, оно автоматически выбирается. Если совпадений несколько, открывается выпадающий список для выбора. При отсутствии совпадений показывается сообщение. До выбора действительного элемента произвольный текст не считается кодом и не может быть сохранён вместо выбранного значения. Можно также сразу выбирать значение из первоначального выпадающего списка.

Период оказания услуги выбирается из удобных вариантов «Один месяц (1)», «Три месяца (3)», «Двенадцать месяцев (12)» либо вводится вручную целым числом 1–255 (тип SQL `tinyint`). Три поля XDD остаются составными (направление, смещение по месяцам, число месяца или «Последний день (99)»). При редактировании показываются реальный код для хранения в `int` и **примерная**, не договорная дата для текущего года. Примерная дата рассчитывается только для подсказки в окне редактирования; в списке все вычисления выполняет SQL. `X99` означает последний день месяца, включая високосный февраль.

## Все настраиваемые SQL-запросы

Все восемь запросов редактируются непосредственно в **«Настройки SQL и колонок…»**. При открытии, переключении запросов и вставке текста редактор **сохраняет исходное расположение SQL**: переносы строк, пустые строки, отступы, табуляцию и пробелы. Используется моноширинный шрифт Consolas. Только кнопка **«Форматировать SQL»** автоматически расставляет отступы и переносы по запросу пользователя. Форматирование не изменяет текст SQL-литералов, комментарии и имена в квадратных скобках. В JSON сохраняется тот SQL, который отображается в редакторе (без необходимости вручную экранировать переносы строк).

| Поле `config.json` | Назначение | Параметры и обязательный результат |
|---|---|---|
| `list_sql` | Обычный список | вход: `@limit`, `@search` (пустая строка для совместимости со старой конфигурацией); результат: `ContractID` и нужные алиасы |
| `search_sql` | Поиск в списке | вход: `@search` и `@limit`; результат: `ContractID` и нужные алиасы |
| `contracts_sql` | Выпадающий список договоров | вход: `@search`, `@selected`, `@limit`; возвращает ровно 2 колонки: **код, название** (в этом порядке) |
| `document_types_sql` | Выбор типа документа основания автооплаты | вход: `@search`, `@selected`, `@limit`; возвращает **код, название** |
| `get_sql` | Чтение редактируемой записи | вход: `@id`; возвращает **ровно 11 колонок в порядке из схемы** (см. ниже) |
| `insert_sql` | Добавление | вход: `@id`, `@type`, `@period`, `@auto`, `@amount`, `@day`, `@month`, `@docs`, `@pay`, `@off`, `@notify` |
| `update_sql` | Обновление | все параметры вставки плюс `@old_type`, `@old_period`, `@old_auto`, `@old_amount`, `@old_day`, `@old_month`, `@old_docs`, `@old_pay`, `@old_off`, `@old_notify` |
| `delete_sql` | Удаление | вход: `@id` |

SQL команды передаются через именованные параметры драйвера: строка поиска, выбранный ID и содержимое полей не конкатенируются в SQL. Для запросов модификации используются `RowsAffected`: при UPDATE/DELETE ожидается ровно одна изменённая строка; иначе выводится ошибка конфликта/отсутствия.

`get_sql` должен вернуть в таком порядке: код договора; код типа документа основания автооплаты; период; автооплата; сумма (`nvarchar`/`decimal(19,4)` без округления в float); день/месяц начала; документы XDD; оплата XDD; отключение XDD; оповещение куратора.

**Важно:** для сохранения защиты от конкурентного изменения в `update_sql` рекомендуется оставлять условия `@old_*` из образца. Если заменить запрос на `UPDATE ... WHERE id=@id`, защита от перезаписи чужих изменений перестанет работать.

## Колонки списка — `list_columns`

Каждый элемент массива имеет **ровно шесть полей**:

```json
{
  "field": "PaymentText",
  "title": "Оплата по договору",
  "width": 305,
  "order": 6,
  "sortField": "PaymentCode",
  "visible": true
}
```

- **`field`** — алиас SQL-колонки для отображения в списке. Он обязательно должен присутствовать **и в `list_sql`, и в `search_sql`** (регистр букв не учитывается).
- **`title`** — заголовок колонки.
- **`width`** — ширина в пикселях (45–1600).
- **`order`** — уникальное положительное число (1 означает первую колонку); порядок массива JSON роли не играет.
- **`sortField`** — SQL-алиас поля для сортировки по нажатию на заголовок. Может отличаться от `field` и может указывать на скрытое поле результата SQL. Например, отображается текст «Оплата по договору», а сортировка идёт по числовому `PaymentCode`. Повторный щелчок переключает направление сортировки.
- **`visible`** — `true`, если колонка видима; `false`, если скрыта. В списке должна быть хотя бы одна видимая колонка.

**Автосинхронизация с SQL:** при обновлении списка, открытии редактора колонок и сохранении настроек приложение сравнивает наборы алиасов двух запросов. Они должны совпадать по составу, но могут различаться порядком. Новые алиасы видимы по умолчанию (`visible:true`, `sortField=field`), а настройки прежних полей остаются неизменными. Если алиас исчез, программа предлагает убрать его настройки; без подтверждения конфигурация остаётся прежней. Если старый `sortField` исчез, он заменяется на `field`, и существующая колонка не теряется. При автоматической записи создаётся `config.json.bak`. SQL-подключение для синхронизации должно быть доступно.

Поля, которые нужны только для сортировки, например `PaymentCode`, уже включены в стандартную конфигурацию как скрытые (`visible:false`), поэтому они не выводятся в новом пустом приложении. В существующем пользовательском `config.json` любой новый обнаруженный SQL-алиас в соответствии с вашим правилом становится **видимым**; при необходимости его можно скрыть через настройки.

`ContractID` обязателен в результате **обоих** запросов для выбора/редактирования записи, но показывать его необязательно. Все `field` и `sortField` проверяются по фактическому набору алиасов SQL, даже если SELECT вернул ноль строк. **Встроенных виртуальных столбцов больше нет:** Go ничего не выводит из `ServicePeriod`, `AutoPay` или XDD для списка. Не перечисляйте в `list_columns` поля, отсутствующие в запросах.

В стандартном `config.example.json` `ServicePeriodText`, `AutoPayText`, `DocumentsText`, `PaymentText` и `DisconnectText` формируются в **самом T-SQL** через `CASE`. К примеру, `ServicePeriodText` равен «Один месяц (1)», «Три месяца (3)», «Двенадцать месяцев (12)» или русскому тексту для произвольного количества месяцев. `PaymentText` объясняет код XDD; `PaymentCode` возвращается отдельным числовым полем для корректной сортировки. Можно расширять SQL JOIN-ами и собственными выражениями, но алиасы должны совпадать с настройками колонок.

Клик по заголовку сортирует **уже загруженные** строки по соответствующему `sortField` (с учётом числовых/денежных/датовых типов возвращённых SQL-значений). Начальный порядок и ограничение `TOP (@limit)` определяет SQL; сортировка на экране не переставляет записи, не попавшие в эту выборку. Чтобы отсортировать весь результат на стороне SQL Server, измените `ORDER BY` в `list_sql` / `search_sql`.

Для старого `config.json` поля `order`, `sortField` и `visible` заполняются автоматически: порядком массива, `field` и `true` соответственно. **Старые виртуальные поля требуют правки SQL:** добавьте вычисление соответствующих алиасов в свои запросы, ориентируясь на новый `config.example.json`; иначе программа предложит удалить отсутствующие поля из `list_columns`. Пользовательские SQL-запросы при обновлении автоматически не переписываются.

## XDD — правила дат

Начало услуги 07.01, период 3 месяца:

| Код SQL `int` | Смысл | Примерный срок |
|---|---|---|
| `9` (`009`) | 9-е число от месяца начала | 09.01 |
| `120` | 20-е число со смещением +1 | 20.02 |
| `-120` | 20-е число со смещением −1 | 20.12 предыдущего года |
| `-6` (`-006`) | 6-е число до начала | 06.01 |
| `306` | не ранее 07.04, ближайшее 6-е | 06.05 |
| `320` | не ранее 07.04, ближайшее 20-е | 20.04 |
| `420` | 20-е со смещением +4 | 20.05 |
| `99` (`099`) | конец января | 31.01 |
| `199` | конец февраля | 28 или 29.02 |

Минус и плюс (относительно начала периода) применяются ко всем трём полям независимо от периода услуги. DD=99 означает последний календарный день соответствующего месяца.

## Сборка и проверка

Репозиторий: https://github.com/Postnn/ServiceAgreement

Push в `main` запускает GitHub Actions (Windows 2022, Go 1.25.x):

1. `go mod tidy`
2. `go test -count=1 -v ./...`
3. `go vet ./...`
4. Встраивание Win32 manifest, сборка EXE c `-H=windowsgui` без окна консоли.
5. ZIP с `ServiceAgreement.exe`, `config.example.json`, `config.json`, инструкцией в Actions artifacts и GitHub Releases.

Приложение standalone (никакой установщик, .NET и ODBC не нужны), но для работы необходим сетевой доступ к MS SQL Server. Тесты автоматически проверяют правила XDD, конфигурацию и внутренние преобразования; доступ к реальной базе и интерактивные операции GUI требуют проверки на вашей стороне.
