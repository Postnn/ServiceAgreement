# ServiceAgreement

Минималистичный редактор `dbo.ДокументыДоговораОказанияУслуг` для **Windows 10/11 x64**, написанный на Go.

## Функциональность

- Окно списка: поиск, обновление, добавление, редактирование (двойной щелчок), удаление с подтверждением. В списке три поля XDD отображаются **понятным описанием** (до/после начала, число месяцев, день/конец месяца) и примером даты.
- Отдельное модальное окно редактирования всех **11** столбцов таблицы. Выбор существующего договора и типа документа через настраиваемые SQL-справочники с поиском.
- Для каждого поля XDD **три раздельных элемента формы**: до/после начала, смещение в месяцах (0, 1, 2...), конкретное число 01–31 или «последний день месяца (99)». Код БД и иллюстративная календарная дата пересчитываются автоматически; вводить «магические цифры» вручную не требуется.
- Прямое соединение с Microsoft SQL Server через pure-Go драйвер `go-mssqldb`, без ODBC и .NET. Для Windows доступна интегрированная аутентификация SSPI.
- Проверка кодов периодов 1/3/12 месяцев, флагов 0/1, дня и месяца, XDD и точной суммы `money` без `float64`.
- Параметризованные INSERT/UPDATE/DELETE, защита от перезаписи изменений другого пользователя при UPDATE (optimistic concurrency).
- Единственный EXE для приложения, без дополнительных DLL; настройки в отдельном файле JSON.

## Запуск

1. Загрузите `ServiceAgreement-windows-amd64.zip` из раздела **Releases** либо из успешно выполненного GitHub Actions workflow.
2. Распакуйте ZIP в папку и откройте находящийся рядом с EXE `config.json`.
3. Укажите `connection_string` своего SQL Server и при необходимости отредактируйте запросы списка и справочников.
4. Запустите `ServiceAgreement.exe` под учётной записью с нужными правами SQL Server.

**Важно:** ZIP содержит **шаблон** `config.json`, а не сведения реального сервера. Не помещайте пароль к БД в GitHub. Для доменной Windows-аутентификации пример использует `trusted_connection=yes` и `encrypt=true`; для TLS сертификат сервера должен быть доверенным. Драйвер поддерживает и SQL-аутентификацию. Пример с SQL-логином:

```text
sqlserver://USER:PASSWORD@sqlhost:1433?database=DB&encrypt=true
```

Пароль в URL должен быть URL-encoded. Если используется SQL-аутентификация, ограничьте права чтения файла `config.json` на Windows. Предпочтительна интегрированная аутентификация.

## Настройка запросов в config.json

В конфигурационный файл вынесены `connection_string`, `list_sql`, `contracts_sql`, `document_types_sql`, а также лимиты строк. Никаких конкретных имён/описаний полей в других справочниках, кроме подтверждённых в DDL, приложение не предполагает: в примере **названия договоров и типов документов совпадают с их кодами**. Настройте SELECT с реальными полями названий вашей БД.

Возвращайте колонки **в указанном порядке**, их псевдонимы произвольные:

| Запрос | Параметры | Результат (колонки по порядку) |
|---|---|---|
| `list_sql` | `@search` nvarchar, `@limit` int | `ContractID` int, `AgreementLabel` string, `ServicePeriod` int, `Amount` string, `AutoPay` int, `StartDay` int, `StartMonth` int, `DocumentsCode` int, `PaymentCode` int, `DisconnectCode` int |
| `contracts_sql` | `@search` nvarchar, `@limit` int, `@selected` int | `ContractID` int, `ContractLabel` string |
| `document_types_sql` | `@search` nvarchar, `@limit` int, `@selected` int | `TypeID` int, `TypeLabel` string |

`@selected` позволяет включать уже выбранную запись при поиске. Запросы **читающие**, задаются администратором — не следует помещать в них изменения данных. Внутренние команды сохранения всегда работают с `dbo.ДокументыДоговораОказанияУслуг` и не настраиваются.

## Даты XDD: смещение месяцев и число/последний день

В **каждом** из трёх полей (`ДеньМесяцаПолученияДокументов`, `ДеньМесяцаОплатыПоДоговору`, `ДеньМесяцаОтключенияУслуги`) используется единый формат `XDD`. `X` может быть отрицательным (`-N`), нулём или положительным (`N`) и задаёт количество месяцев относительно **дня и месяца начала периода оказания услуги**, а не только календарного месяца. Знак определяет сторону: **отрицательный код — до начала (предоплата)**, положительный — после/от начала. Это правило применяется и к получению документов и отключению.

`DD`: число `01–31` **либо `99` — последний календарный день соответствующего месяца**. Последнее автоматически превращается в 28, 29, 30 или 31; в феврале високосного года будет 29 февраля. Допускается и `X=0`: ведущие нули из `009`/`099` не хранятся в колонке `int`. В том числе:

- `009` → `9`; `-006` → `-6` (знак отличает срок до начала);
- `099` → `99` (конец месяца, нулевое смещение); `-099` → `-99`;
- `199` → `199`; `-199` → `-199`; `399` → `399`;
- значения `100`, `198`, `132` и `0` **недопустимы** (`00`, `98`, `32` не входят в `DD`).

### Примеры для трёхмесячной услуги с началом 07.01.2026

| Человеческое описание | Код в БД | Иллюстративный срок |
|---|---:|---|
| Оплата к 9-му числу от начала | `9` (ввод `009`) | 09.01.2026 |
| Оплата к 20-му числу через месяц | `120` | 20.02.2026 |
| Предоплата к 20-му числу за месяц | `-120` | 20.12.2025 |
| Предоплата до 6-го числа непосредственно перед началом | `-6` | 06.01.2026 |
| К 6-му числу через три полных месяца | `306` | **06.05.2026** (06.04 услуга ещё действует) |
| К 20-му числу через три полных месяца | `320` | **20.04.2026** |
| К 20-му числу через четыре полных месяца | `420` | **20.05.2026** |
| В последний день месяца начала периода | `99` | 31.01.2026 |
| В последний день после трёх полных месяцев | `399` | 30.04.2026 |
| Предоплата в последний день предыдущего месяца | `-99` | 31.12.2025 |

**Правило примера:** отсчитываем `|X|` месячных границ от *дня* старта (для `+3` от 07.01 попадаем на 07.04), затем берём первое наступление дня `DD` на соответствующей стороне. Поэтому `306` — 06.05, а не 06.04. Для `-N` (N≥1) ищется день внутри N-го месячного интервала **до** старта; для отрицательного нуля — ближайшее подходящее число до начала. Для месяцев без указанного 29/30/31 числа форма предлагает использовать `99`.

Дата рядом с кодом в окнах приложения рассчитана **как пример для начала цикла в текущем году** по полям `ДеньМесяцаНачалаОказанияУслуги` и `МесяцНачалаОказанияУслуги`. Поскольку в таблице не хранится год конкретного оплаченного периода, это **не фактический крайний срок конкретного платежа**. Не используйте пример для автоматического списания, отключения или правовых сроков. Настройки БД сохраняют только сам код XDD.

> Для реального применения необходимо согласовать с владельцем бизнес-логики поведение 29–31-го числа в несуществующие дни некоторых месяцев. В текущем редакторе коды сохраняются, а пример может показывать, что дата в данном интервале не существует.

**Важно при обновлении старой версии приложения:** для читаемого списка `list_sql` теперь обязан возвращать **10 колонок** (см. таблицу выше). Используйте обновлённый `config.example.json` либо добавьте в свой `list_sql` пять полей `StartDay`, `StartMonth`, `DocumentsCode`, `PaymentCode`, `DisconnectCode` в описанном порядке.

## Безопасность данных

- При редактировании существующей записи её первичный ключ (документ договора) не изменяется.
- При вставке используется текущий документ договора, который уже должен существовать в `dbo.ДокументыДанные`. SQL Server проверяет внешние ключи.
- При удалении удаляется **только** строка параметров из таблицы `ДокументыДоговораОказанияУслуг`, не документ в `ДокументыДанные`.
- При конкурентном изменении записи UPDATE не перезаписывает значения другого пользователя и предлагает обновить список.
- Доступ к БД ограничен правами пользователя; автоматической выдачи разрешений нет.
- Удаление выполняется после диалога подтверждения. Перед первым запуском на рабочих данных рекомендуется резервная копия.
- Приложение изменяет данные непосредственно SQL, **не вызывает** функции legacy DocView и может обходить прикладные события/уведомления legacy системы. Существующие триггеры SQL Server отработают как обычно.

### Замечание о схеме

В предоставленном DDL присутствует `DEFAULT` на поле `ШаблонОписанияСлужебкиНаОплату`, хотя оно отсутствует в `CREATE TABLE`. Этот столбец в редакторе не используется. Если реальная таблица содержит дополнительные `NOT NULL` столбцы без значений по умолчанию, операция INSERT потребует адаптации схемы или SQL команды.

## Разработка и CI

Структура:

- `cmd/serviceagreement/main_windows.go` — Win32 GUI (Walk), две формы;
- `internal/core/core.go` — конфигурация, бизнес-валидация и MSSQL CRUD;
- `internal/core/xdd.go` — сборка/разбор XDD, описание, иллюстративное разрешение в дату с учётом конца месяца и високосного года;
- `internal/core/core_test.go` — автоматические тесты;
- `app.manifest` — Common Controls 6 + DPI manifest, встраивается в EXE;
- `.github/workflows/windows.yml` — Windows runner: `go test`, `go vet`, компиляция, ZIP, Actions artifact и prerelease на `main`.

Запустить тесты: `go test ./...` (для нативного интерфейса — под Windows); SQL интеграционный тест не выполняется без отдельной тестовой БД.

**CI не может доказать реальную работоспособность запросов против вашей прикладной БД:** после загрузки следует сделать пробное чтение/редактирование в тестовой базе.
